# Workflow

End-to-end workflow documentation for the Cleaning Company Management System.

---

## 1. Customer Booking Workflow

### Step 1 — Customer Visits Website

Customer lands on the public website. They read about the services, view the gallery, and decide to book.

Entry points:
- Landing page → CTA "Book a Cleaning"
- Services page → "Book This Service"
- Navigation → "Book Now"

### Step 2 — Customer Fills Booking Form (`/book`)

Multi-step form captures:

1. Service type (standard, deep, end of tenancy, etc.)
2. Property details (address, type, bedrooms, bathrooms)
3. Preferred schedule (date, arrival window, alternative date)
4. Job details (tasks, extras, pets, hazards, keys, alarm, notes)
5. Optional photos
6. Contact info (name, email, phone)
7. Review and submit

### Step 3 — Booking Submitted

System:
- Creates or finds customer record (upsert by email)
- Creates `bookings` record (status: `new_enquiry`)
- Generates booking reference (CLS-YYYY-XXXX)
- Stores any uploaded photos to `booking-photos` bucket
- Inserts audit log entry
- Sends email notification to admin
- Redirects customer to `/book/confirmation?ref=CLS-2026-0001`

## 2. Admin Review Workflow

### Step 1 — Admin Reviews Enquiry

Admin sees new enquiry in:
- Dashboard KPI card "New Enquiries"
- Enquiries list `/dashboard/enquiries`
- Email notification

Admin opens enquiry detail.

### Step 2 — Admin Takes Action

Admin can:
- Mark "Under Review" (status: `under_review`)
- Review customer details and uploaded photos
- Add internal notes
- Contact the customer (external — phone or email)
- Modify booking details if needed
- Reject/spam (status: `rejected`)
- Proceed to create a quotation

---

## 3. Quotation Workflow

### Step 1 — Admin Creates Quote

From the enquiry detail → "Create Quote" opens the quote builder at `/dashboard/quotes/new?bookingId=`.

Admin fills in:
- Appointment date + time
- Line items (service, extras, custom items)
- Discount (optional)
- VAT (optional)
- Expiry date
- Terms text

Admin saves as draft or sends immediately.

### Step 2 — Quote Sent to Customer

On "Send":
- Quote status → `sent`
- Booking status → `quotation_sent`
- System generates a unique public token
- Email sent to customer with link: `https://[domain]/q/[token]`
- Audit log entry

### Step 3 — Customer Views Quote (`/q/[token]`)

- No login required
- Customer sees a styled, read-only quote
- `viewed_at` timestamp recorded on first open
- Quote status → `viewed`

Customer has three options:

**A. Accept**
- Customer checks "I agree to the terms"
- Selects payment method (Bank Transfer / Cash)
- Clicks "Accept Quote"
- Records: `accepted_at`, `accepted_ip`, `accepted_device`
- Quote status → `accepted`
- Booking status → `quotation_accepted`
- **Triggers: Invoice Generation (see Section 4)**

**B. Request Changes**
- Customer leaves a message
- Quote status → `change_requested`
- Admin notified
- Admin creates a new quote version

**C. Decline**
- Quote status → `declined`
- Booking status can be manually updated by admin

### Step 4 — Quote Expiry

If the expiry date passes and the quote is still `sent` or `viewed`:
- Status → `expired` (detected on read or via scheduled function)

## 4. Invoice Generation Workflow

### Trigger

Customer accepts the quotation.

### Steps

Automatic (server action triggered on acceptance):

1. Create `invoices` record:
   - Linked to: booking, accepted quote, customer
   - `invoice_number` = INV-YYYY-XXXX (auto-generated by DB trigger)
   - Status = `unpaid`
   - Due date = 7 days from now (configurable)
2. Generate PDF (rendered and stored to Supabase Storage)
3. Booking status → `invoice_generated`
4. Email sent to customer with invoice link: `https://[domain]/i/[token]`
5. Audit log entry

## 5. Job Assignment Workflow

### Step 1 — Admin Assigns Cleaner

From job detail (`/dashboard/jobs/[id]`):

1. Admin clicks "Assign Cleaner"
2. Admin selects:
   - Cleaner (filtered by status = `available`)
   - Scheduled date
   - Scheduled time
3. System:
   - Creates `jobs` record (if not exists) linked to booking
   - Sets `jobs.cleaner_id`
   - Sets `jobs.scheduled_date` and `scheduled_time`
   - Generates `secure_token` (UUID)
   - Booking status → `cleaner_assigned`
   - Audit log entry

### Step 2 — Admin Copies Secure Link

The secure job link is displayed:

```
https://[domain]/jobs/[secure-token]
```

Admin copies and sends to cleaner via WhatsApp manually.

No automatic WhatsApp sending in MVP.

## 6. Cleaner Workflow

### Step 1 — Cleaner Opens Secure Link

Cleaner receives WhatsApp message with link from admin.

**If already logged in:**
→ Redirected directly to the job page

**If not logged in:**
→ Redirected to `/auth/v2/login?next=/jobs/[token]`
→ After successful login, redirected back to `/jobs/[token]`

### Step 2 — Secure Link Resolves to Job

`/jobs/[token]`:
- Looks up `jobs.secure_token = token`
- Verifies `jobs.cleaner_id = auth.uid()` (RLS enforces this)
- If mismatch → 404/unauthorized
- If match → redirects to `/cleaner/jobs/[id]`

### Step 3 — Cleaner Views Job

Cleaner sees:

- Customer name, address, phone
- Service type, notes, date, time
- Current job status

### Step 4 — Cleaner Accepts or Declines

**Accept:**
- Job status updates (booking status → `cleaner_accepted`)
- `jobs.accepted_at` = now
- Admin notified

**Decline:**
- `jobs.declined_at` = now
- `jobs.declined_reason` saved
- Booking status → `cleaner_assigned` (unassigned at job level, back to admin)
- Admin notified

### Step 5 — Cleaner Starts Job

Cleaner clicks "Start Job":
- Booking status → `in_progress`
- `jobs.started_at` = now
- Before photo upload section unlocks

### Step 6 — Before Photos

Cleaner uploads before photos:
- Photos stored in `job-photos` bucket
- Category = `before`
- Metadata: booking_id, uploaded_by, timestamp

### Step 7 — Cleaner Completes Work

After completing the cleaning, cleaner uploads after photos:
- Photos stored in `job-photos` bucket
- Category = `after`
- Adds completion notes (optional)

### Step 8 — Cleaner Submits Completion

Cleaner clicks "Complete Job":
- Booking status → `completed_pending_review`
- `jobs.completed_at` = now
- Admin notified

---

## 7. Job Review & Closure

### Step 1 — Admin Reviews Completion

Admin opens job detail:
- Views before/after photos
- Reviews cleaner notes
- Assesses completion quality

### Step 2 — Admin Approves

Admin clicks "Approve":
- Booking status → `completed`
- Audit log entry
- Customer notified (optional, MVP)

If issue raised:
- Admin clicks "Raise Issue"
- Booking status → `issue_raised` (admin handles resolution separately)

---

## 8. Payment Workflow

### Step 1 — Admin Records Payment

From invoice detail (`/dashboard/invoices/[id]`):

Admin clicks "Record Payment":
- Enters: amount, method (bank transfer / cash), reference, date, notes
- Creates `payments` record
- Recalculates `invoices.amount_paid`

If fully paid:
- Invoice status → `paid`
- Booking status → `paid`
- `invoices.paid_at` = now
- Audit log entry

If partial:
- Invoice status → `part_paid`

## Status Machines Summary

### Booking Status Flow

```
new_enquiry
  → under_review
      → quotation_sent
          → quotation_accepted
              → invoice_generated
                  → cleaner_assigned
                      → cleaner_accepted
                          → in_progress
                              → completed_pending_review
                                  → completed
                                      → paid
      → rejected           (from under_review)
      → cancelled          (any stage, admin action)
      → issue_raised       (from completed_pending_review)
```

### Quote Status Flow

```
draft → sent → viewed → accepted
                      → change_requested → (new version: draft)
                      → declined
              → expired
```

### Invoice Status Flow

```
draft → issued → unpaid → part_paid → paid
                        → overdue
               → cancelled
               → credited
```

### Job Status (internal, via booking status)

```
[booking: cleaner_assigned]
  → [booking: cleaner_accepted]     (cleaner accepts)
  → [booking: in_progress]          (cleaner starts)
  → [booking: completed_pending_review]  (cleaner completes)
  → [booking: completed]            (admin approves)
  → [booking: issue_raised]         (admin flags issue)
```
